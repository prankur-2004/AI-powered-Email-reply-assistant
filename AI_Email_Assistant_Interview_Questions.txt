--------------------------------------------------------------------------------
1. PROJECT OVERVIEW & HIGH-LEVEL ARCHITECTURE
--------------------------------------------------------------------------------

Q1: Can you explain the high-level architecture of your AI-Powered Email Reply Assistant?
Answer:
- The system follows a decoupled Full-Stack Architecture.
- Frontend: Single Page Application built with React 19, Vite, and Tailwind CSS. Communicates with backend via REST API calls using Axios with JWT interceptors.
- Backend: Django 6.1 web application with Django REST Framework (DRF) handling user authentication, email storing, RAG vector retrieval, and prompt processing.
- AI Integration: Uses Google Gemini API (`gemini-3.6-flash`) for email intent/sentiment analysis and context-aware email reply generation.
- RAG & Vector Engine: Converts personal knowledge into high-dimensional vector embeddings, computes cosine similarity against incoming email context, and injects relevant knowledge into Gemini prompts dynamically.

Follow-Up Questions:
  * FU 1.1: Why did you choose Django REST Framework for the backend instead of FastAPI or Node.js/Express?
    - Talking Points: Django provides built-in ORM security (SQL injection protection), robust authentication support (`rest_framework_simplejwt`), structured app layout (`accounts`), and rapid development speed.
  * FU 1.2: How does data flow when a user clicks "Generate AI Reply"?
    - Talking Points: Frontend triggers `POST /api/auth/emails/<id>/reply/` -> Backend preprocesses raw HTML email -> Conducts semantic search on user's personal knowledge base -> Retrieves past conversation history -> Builds structured prompt -> Calls Gemini API -> Runs response validator -> Saves generated reply -> Returns clean reply to Frontend.

2. AI ENGINE & GOOGLE GEMINI INTEGRATION
--------------------------------------------------------------------------------

Q2: How is Google Gemini integrated into your application, and what model version do you use?
Answer:
- We use the `google-genai` Python SDK connected to the `gemini-3.6-flash` model.
- Key implementation functions:
  1. `analyze_email()`: Extracts Intent (meeting/inquiry/request), Sentiment (positive/neutral/negative), Urgency (high/normal/low), Topic, Key Entities, and Summary.
  2. `generate_email_reply()`: Accepts cleaned email text, email analysis, prior conversation context, user tone/length preferences, and retrieved personal knowledge items.

Follow-Up Questions:
  * FU 2.1: Why `gemini-3.6-flash` instead of `gemini-pro` or OpenAI GPT-4?
    - Talking Points: Low latency, highly cost-effective for short text tasks, excellent instruction-following capabilities for structured system prompts.
  * FU 2.2: How do you handle Gemini API rate limits or downtime?
    - Talking Points: Wrapped API calls in try-except blocks, raising custom `RuntimeError` exceptions with detailed diagnostics. Future improvements include implementing backoff retries using libraries like `tenacity` or Celery task queues.
  * FU 2.3: How do you prevent Gemini from inventing false information (hallucinations)?
    - Talking Points: System prompt rules explicitly state: "Do not invent names, dates, times, companies, or other missing information. Do not make claims not supported by the email or personal knowledge base."

3. RAG (RETRIEVAL-AUGMENTED GENERATION) & VECTOR EMBEDDINGS
--------------------------------------------------------------------------------

Q3: What is RAG, and how did you implement it in this project?
Answer:
- RAG stands for Retrieval-Augmented Generation. Instead of relying solely on the LLM's pre-trained data, we retrieve user-specific context (e.g., career background, skills, preferences) from a database and inject it into the prompt.
- Implementation Pipeline:
  1. User stores facts in `PersonalKnowledge` (e.g., "I know Python, Django, React").
  2. Text is converted into vector embeddings via `generate_embedding()`.
  3. When generating a reply, the incoming email query is vectorized.
  4. Cosine similarity score is computed between email vector and knowledge vectors.
  5. Top-K relevant knowledge items above a similarity threshold are injected into the Gemini prompt.

Follow-Up Questions:
  * FU 3.1: How do you compute cosine similarity in Python/Django?
    - Talking Points: Dot product of normalized vectors: `cosine_sim = dot(v1, v2) / (norm(v1) * norm(v2))`.
  * FU 3.2: What embedding model do you use, and what is its vector dimension?
    - Talking Points: Uses Google's embedding model producing 3072-dimensional vector representations.
  * FU 3.3: How would you scale the RAG search if a user had 1,000,000 personal knowledge entries?
    - Talking Points: Transition from in-memory/Python calculation to a dedicated vector database such as pgvector (PostgreSQL extension), Pinecone, Qdrant, or Milvus using HNSW (Hierarchical Navigable Small World) indexing.

4. EMAIL PREPROCESSING & RESPONSE VALIDATION
--------------------------------------------------------------------------------

Q4: What preprocessing is done on incoming raw emails before sending them to the LLM?
Answer:
- Raw emails often contain HTML tags, inline CSS, email signatures, and nested quote chains (`> On Date, X wrote:`).
- `preprocess_email()` strips HTML tags using BeautifulSoup / Regex, removes quoted historical replies to prevent prompt clutter, normalizes whitespace, and extracts clean plain text.

Follow-Up Questions:
  * FU 4.1: Why is response validation necessary after Gemini generates a reply?
    - Talking Points: LLMs can sometimes output unwanted artifacts like placeholder bracket text (`[Your Name]`, `[Insert Date]`), subject line headers (`Subject: Re:`), or double sign-offs.
  * FU 4.2: How does `response_validator.py` clean up generated replies?
    - Talking Points: Uses regex to strip subject prefixes, detects and removes placeholder tokens (`[Name]`, `[Date]`), fixes joined/merged words, and ensures proper spacing and greeting/sign-off formatting.

5. SECURITY, JWT AUTHENTICATION & CORS
--------------------------------------------------------------------------------

Q5: How do you handle security and user authentication in the app?
Answer:
- Authentication: Token-based stateless authentication using JWT (JSON Web Tokens) via `djangorestframework-simplejwt`.
- Login endpoint `/api/auth/login/` returns short-lived `access_token` and long-lived `refresh_token`.
- Axios Interceptor on React frontend automatically attaches `Authorization: Bearer <access_token>` to every HTTP request.
- Automatic Refresh: If an API request returns `401 Unauthorized`, the interceptor calls `/api/auth/token/refresh/` using the refresh token, updates the access token in `localStorage`, and retries the failed request seamlessly.

Follow-Up Questions:
  * FU 5.1: How do you protect against CORS issues in production?
    - Talking Points: Configured `django-cors-headers` middleware. In production settings, `CORS_ALLOWED_ORIGINS` is dynamically loaded from environment variables to permit only trusted domain origins.
  * FU 5.2: Where are sensitive API keys stored?
    - Talking Points: Stored in `.env` files and loaded via `python-dotenv` / system environment variables. Never committed to version control (`.gitignore`).
  * FU 5.3: How do you enforce authorization so User A cannot read User B's emails?
    - Talking Points: Django views filter database queries using `request.user`: e.g., `Email.objects.filter(user=request.user)`.

6. FRONTEND ARCHITECTURE & UX DESIGN
--------------------------------------------------------------------------------

Q6: What frontend technologies and design choices did you make?
Answer:
- React 19 + Vite for ultra-fast HMR and bundle compilation.
- Styling: Tailwind CSS v4 featuring modern dark mode, glassmorphism backdrop blurs, indigo/purple/cyan glow gradients, and responsive split-pane layout.

Follow-Up Questions:
  * FU 6.1: How do you handle inline editing of an AI reply before accepting it?
    - Talking Points: When clicking "Edit", UI toggles plain text rendering into an interactive `<textarea>` bound to `editedReply` state. Saving triggers `PATCH /api/auth/replies/<id>/edit/`.
  * FU 6.2: How does the AI Feedback system work?
    - Talking Points: Users can rate replies (1-5 stars), mark Thumbs Up/Down (`is_helpful`), and leave comments. Sent via `POST /api/auth/replies/<id>/feedback/` to help train and evaluate prompt quality over time.


--------------------------------------------------------------------------------
7. DATABASE SCHEMAS & CONVERSATION THREADING
--------------------------------------------------------------------------------

Q7: What database models did you design for this application?
Answer:
1. `Email`: Stores `user`, `sender`, `recipient`, `subject`, `body`, `conversation_id`, `is_read`, `created_at`.
2. `EmailAnalysis`: Stores `email` 1-to-1 link, `intent`, `sentiment`, `urgency`, `topic`, `summary`, `entities`.
3. `AIReply`: Stores `email` link, `generated_reply`, `status` (draft/accepted/edited), `created_at`.
4. `AIReplyFeedback`: Stores `ai_reply` link, `rating` (1-5), `is_helpful`, `comment`.
5. `PersonalKnowledge`: Stores `user`, `title`, `content`, `embedding` vector payload.
6. `UserPreference`: Stores `user`, `tone`, `reply_length`, `greeting`, `sign_off`.

Follow-Up Questions:
  * FU 7.1: How does the assistant handle conversation history across multiple replies?
    - Talking Points: Emails share a `conversation_id`. When replying to an email, `conversation_service.py` fetches prior emails and generated replies with the same `conversation_id`, formatting them into historical dialogue context for Gemini.

8. TRADEOFFS, CHALLENGES & FUTURE IMPROVEMENTS
--------------------------------------------------------------------------------

Q8: What was the biggest challenge you faced during development?
Answer:
- Challenge: Ensuring generated email replies remained conversational and natural without making assumptions or inventing facts when missing user context.
- Solution: Combined RAG personal knowledge injection with prompt strictness rules and post-generation regex validators (`response_validator.py`).

Q9: If you had more time, what features would you add next?
Answer:
1. OAuth 2.0 Integration with Gmail & Outlook APIs for live inbox synchronization.
2. Background task processing using Celery & Redis for asynchronous email ingestion and batch AI replies.
3. Pgvector extension integration for hardware-accelerated SQL vector indexing.
4. WebSocket / Server-Sent Events (SSE) for streaming Gemini reply generation word-by-word into the UI.
